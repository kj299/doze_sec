# benign_corpus.txt -- known-BENIGN artifacts that look like attacks.
#
# Read by tools/benign_corpus_check.ps1. Every entry is a false-positive
# twin: something a real machine carries that resembles an indicator, and
# that the audit must report as context (OK/INFO), or as a finding a person
# can adjudicate with the note below. Two of these fired as ACTIVE COMPROMISE
# on the owner's own machine in 2026-08 (P9NP, Event 104) because they had
# never been tested; a third (never-onboarded Sense) contradicted its own
# summary. For this audience a false "you are compromised" is the most
# harmful output the tool can produce.
#
# FORMAT -- INI-style blocks (regex-safe; the '|' corpora cannot hold regexes):
#   [id]                    short slug, unique
#   class     = QUIET       the tool prints a CONTEXT line for the benign twin;
#                           every report line matching `signature` must carry
#                           a leading tag <= maxsev (OK < INFO < WARNING < CRITICAL).
#                           -Mode Report FAILS on a higher tag.
#             = ADVISE      `signature` is the FINDING-shaped line that has a
#                           known benign cause; on a real machine a match prints
#                           the note (how to verify). The human adjudicates;
#                           never a failure.
#   maxsev    = OK|INFO|WARNING   (QUIET only)
#   proof     = harness:<Name substring of an Invert=$true case in tests/detection_selftest.ps1>
#             | ci:<step-name substring in .github/workflows/windows-smoke.yml>
#             | field:<why this cannot be planted -- observable only on a real machine>
#             several proofs: separate with ';'
#   signature = .NET regex matched per report line
#   note      = origin, and how a person verifies it on their machine
#
# -Mode Lint fails on: an entry without class/proof/signature/note, an
# unresolvable proof, an invalid regex, a harness Invert case that no entry
# catalogues (every false-positive guard must be documented here), or fewer
# than 10 entries (vacuous). -Mode Report is run by tests/field_test.ps1 on a
# real machine and by the harness on its own report.

# ---- QUIET: the audit prints context, and must keep it at or below maxsev ----

class     = QUIET
maxsev    = INFO

signature = BITS job '[^']+' is \d+ days old
note      = Browser and OS updaters park long-lived BITS jobs for weeks at a time; Microsoft Edge's 'Edge Component Updater' is the common one. CONFIRMED on the owner's machine 2026-09-13: that job, created 2026-08-09 with NO notify command line, was raised as '[WARNING] ... older than 30 days' purely because it crossed the 30-day threshold between two runs -- it had been 29 days old during the previous run. Nothing on the machine changed; the finding reported a birthday. It was also the SAME job the notify-command arm had already been fixed for, so the false positive returned through the other rule. T1197 persistence executes through the notify command line, so a long-parked job without one can only move bytes, and the destination is what matters. Age alone is now context at INFO with the destination shown. IT THEN CAME BACK A THIRD TIME, through the destination rule written to replace the age rule. On 2026-09-19 the same job was raised as '[WARNING] ... it fetches over plain HTTP, not HTTPS (http://msedge.b.tlu.dl.delivery.mp.microsoft.com/filestreamingservice/files/...)'. Microsoft documents *.dl.delivery.mp.microsoft.com as HTTP on port 80 for Edge content delivery and states: 'Be sure not to use HTTPS for those endpoints that specify HTTP, and vice versa. The connection will fail.' Plain HTTP there is REQUIRED, not a signal -- the payloads are signed and hash-verified separately -- so that branch is deleted, and a CI case now pins the real remote as something that must NOT raise. What still raises: a bare PUBLIC IP address, a write directly into an autostart folder, an unreadable file list, or a notify command line. Verify: Get-BitsTransfer -AllUsers | Select-Object DisplayName,OwnerAccount,CreationTime,JobState and inspect FileList RemoteName.
